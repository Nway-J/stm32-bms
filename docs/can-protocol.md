# 当前 CAN 协议（静态源码描述）

本文描述当前 ECU_A 发送与 ECU_B 解析的业务帧格式。它不是经过总线测试、兼容性认证或量产冻结的协议规范。

## 通用约定

- 帧使用 **11 位标准 CAN 标识符**。
- 下列业务帧的 DLC 均为 **8**。
- 多字节字段采用高字节先（big-endian）：`value = (byte0 << 8) | byte1`。
- 保留字节在 ECU_A 当前发送实现中填零；接收方不应据此假设未来版本永远为零。

## 0x301：单体电压、SOC 与充放电状态

| 字节 | 名称 | 当前编码 |
| --- | --- | --- |
| 0-1 | 单体电压字段 | `uint16_t(v_cell * 100)`，高字节在 byte0、低字节在 byte1；量化单位为 **0.01 V**。 |
| 2 | SOC | 0-100，单位 %。 |
| 3 | 充放电状态 | `0` 空闲/待机、`1` 放电、`2` 充电。 |
| 4-7 | 保留 | 当前填零。 |

重要：当前源码的 0x301 电压字段**不是 mV**，而是 `v_cell × 100` 的 0.01 V 量化值。例如 4.15 V 编码为 415。ECU_B 虽以 `raw / 100` 与 `raw % 100` 取整数、余数，却用 `"%d.%03dV"` 格式化：raw 为 415 时实际显示为 `4.015V`，而不是 `4.15V` 或 `4.150V`。此外，ECU_B 的 USART 调试输出把该 raw 值标为 `mV`。因此当前 OLED 与 USART 的电压显示/标注均不应视为正确比例；迁移或修复时应统一为真正 mV，或统一字段比例与对应小数位，并同步 ECU_A 编码、ECU_B 解码、显示格式、变量命名和文档。

## 0x302：温度

| 字节 | 名称 | 当前编码 |
| --- | --- | --- |
| 0 | 温度 | 摄氏温度的整数值。当前 ECU_A 以 `(uint8_t)(temp_c + 0.5f)` 编码。 |
| 1-7 | 保留 | 当前填零。 |

当前实现使用无符号字节，不能无歧义表达负温度；尽管温度换算函数的理论范围包含负值，传输编码的该限制尚未处理。

## 0x303：故障位掩码

| 字节 | 位/字段 | 含义 |
| --- | --- | --- |
| 0 | Bit0 | 过压。 |
| 0 | Bit1 | 欠压。 |
| 0 | Bit2 | 过温。 |
| 0 | Bit3-6 | 保留。 |
| 0 | Bit7 | 自检失败（ECU_A 自检失败时设置 `g_fault_code = 0x80`）。 |
| 1-7 | 保留 | 当前填零。 |

ECU_A 在故障状态中约每 500 ms 发送该帧。ECU_B 当前的 `fault_str` 只处理 Bit0、Bit1、Bit2；Bit7 虽可被接收保存，但不会形成可读的自检失败提示。

## 当前局限

- 帧中没有版本、序号、时间戳、CRC 或端到端一致性机制；接收状态依赖最近接收时间与当前实现逻辑。
- ECU_B 过滤器全收，`Dash_UpdateData()` 在 `default` 分支后仍更新 `last_rx_tick`，且未校验目标 ID 和最小 DLC；任何成功接收的标准数据帧都可能延长 CAN LOST 判定，DLC 过短的目标帧也可能被解析。
- 0x301 的编码比例、OLED 小数位格式与 USART 的 mV 标注不一致；在未统一为真正 mV 或一致的比例/小数位前，不能将当前显示或调试输出当作正确电压值。
- 温度字段没有符号位定义，负温度编码需要在后续协议修订时明确。
- 协议内容来自当前源码静态读取，不表示本轮已完成实际 CAN 抓包、联调、编译或上板验证。
