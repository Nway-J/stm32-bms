# CAN协议与失效显示

标准帧、500kbit/s、DLC=8。代码定义见两端 `Bsp/can_protocol.h`；发送路径见ECU-A `app_can_service.c`，接收见ECU-B `app_dash.c`。

| ID | 周期 | Byte0 | Byte1 | Byte2 | Byte3 | Byte4 | Byte5~6 | Byte7 |
|---|---|---|---|---|---|---|---|---|
| 0x301 | 100ms | 电压mV高8位 | 电压低8位 | 简化SOC% | 监测状态 | Alive低4位 | 0 | CRC8 |
| 0x302 | 500ms | 整数温度℃ | 0 | 0 | 0 | Alive低4位 | 0 | CRC8 |
| 0x303 | 100ms及故障变化 | 故障高8位 | 故障低8位 | 0 | 0 | Alive低4位 | 0 | CRC8 |

电压或温度快照无效/过期时，对应发送函数直接返回。接收端经过超时后提示失效，故障帧仍可报告原因。温度当前以uint8编码，负温度没有正确的协议表达，后续应设计带符号或偏移编码并同步升级两端。

每种报文有独立Alive Counter，0~15循环。测量值保持不变是正常的；计数器用来辅助检查发送序列是否继续推进、重复或跳号，不能防重放，也不是安全认证。计数器在组包后递增，因此发送失败也可能在接收端表现为跳号。

CRC采用CRC-8/SAE-J1850参数：poly=0x1D、init=0xFF、xorout=0xFF，不反射，覆盖Byte0~6，结果在Byte7。CAN控制器有自身链路CRC；此处额外校验应用负载，但不覆盖CAN ID、没有Data ID、没有认证密钥，不能称为完整AUTOSAR E2E或防攻击方案。

| 接收流 | 超时门限 | 目的 |
|---|---:|---|
| 电压 | 500ms | 避免显示旧电压却误以为仍是实时值 |
| 温度 | 1500ms | 与500ms发送周期匹配 |
| 故障状态 | 500ms | 通信丢失不能解释为没有故障 |

电压通信丢失提示设有2000ms保持参数，短暂丢失不会只闪一下。超时、CRC错误与Alive错误是不同诊断，应结合各自计数检查。串口每秒抽样打印的Alive经常跳数，不等于CAN实际漏帧。
